# Слежение за конкурсными списками МАИ

Раз в 5 минут проверяет позицию абитуриента в списках на
[priem.mai.ru/rating](https://priem.mai.ru/rating/), пишет историю в CSV и
показывает уведомление, когда место или статус изменились.

Зависимостей нет — только стандартная библиотека Python 3.10+.

## Запуск

УКП в коде не хранится — задаётся ключом или переменной окружения:

```bash
python3 mai_rating.py --ukp 1234567    # цикл, проверка раз в 5 минут

export UKP=1234567                     # или один раз в окружении
python3 mai_rating.py                  # цикл
python3 mai_rating.py --once           # одна проверка и выход
```

Полезные ключи:

| Ключ | Что делает |
|------|------------|
| `--ukp 1234567` | чей УКП отслеживать (обязателен, если нет `UKP` в окружении) |
| `--interval 300` | секунд между проверками |
| `--filters prior` | галочки «Отбор»; `--filters` без значений — без фильтров |
| `--csv history.csv` | файл истории |
| `--no-notify` | не дёргать `notify-send` |
| `--once` | одна проверка вместо цикла |

Значения `--filters` соответствуют галочкам на сайте:
`sogl` — с согласием/договором, `osn` — основной высший приоритет,
`prior` — высший проходной приоритет, `dorm` — нуждаемость в общежитии,
`zachisl` — зачисленные, `not_zachisl` — без зачисленных.

Что отслеживать по умолчанию — константы в начале `mai_rating.py`
(`SELECTION`, `FILTERS`, `INTERVAL_SECONDS`).

## Уведомления в Telegram

Если заданы переменные окружения `TG_BOT_TOKEN` и `TG_CHAT_ID`, при изменении
места дополнительно уходит сообщение в Telegram:

```bash
export TG_BOT_TOKEN=123456:AA...
export TG_CHAT_ID=987654321
python3 mai_rating.py
```

Как получить: бот — у [@BotFather](https://t.me/BotFather) командой `/newbot`
(в ответ придёт токен); свой `chat_id` — написать боту любое сообщение и
открыть `https://api.telegram.org/bot<ТОКЕН>/getUpdates`, там будет
`"chat":{"id":...}`.

## Запуск в GitHub Actions

`.github/workflows/rating.yml` запускает `--once` по расписанию и коммитит
`history.csv` обратно в репозиторий — благодаря этому проверка знает прошлое
состояние и шлёт уведомление только при изменении.

Нужны три секрета репозитория (Settings → Secrets and variables → Actions):
`UKP`, `TG_BOT_TOKEN`, `TG_CHAT_ID`. УКП передаётся секретом и в CSV не
пишется, так что в публичном репозитории он не светится.

Два «но»:

* Репозиторий должен быть **публичным**. В приватном бесплатны 2000 минут в
  месяц, а прогон раз в 5 минут — это ~290 минут в сутки.
* Раннеры GitHub находятся за пределами РФ. Если `public.mai.ru` режет
  зарубежные IP, воркфлоу упадёт на запросе — проверяется первым же ручным
  запуском (`Actions` → workflow → `Run workflow`).

## Как это устроено

Страница `/rating/` — каскад из пяти `<select>`. Каждый подгружает статический
фрагмент с `public.mai.ru/priem/rating/data/<id>.html`, где `<id>` накапливает
выбор: `p20260820131238_1_l5_p1_f1_s5`. Префикс — метка снимка, она меняется
каждые несколько минут, старые фрагменты сразу отдают 404. Поэтому цепочка
разрешается заново на каждой проверке — по видимым названиям пунктов, а не по
сохранённому URL.

Два подводных камня, заложенных в код:

* `public.mai.ru` отвечает **404** на `User-Agent` по умолчанию из `urllib` —
  нужен браузерный заголовок.
* Галочки «Отбор» работают на клиенте: сайт прячет строки с CSS-классом
  (`not_pr` для «высшего проходного приоритета») и заново нумерует оставшиеся.
  Место считается так же — внутри своего раздела (`<tbody class="data">`),
  потому что сайт нумерует каждый раздел отдельно.

## Тесты

```bash
python3 -m unittest discover -s tests
```

Фикстуры в `tests/fixtures/` — реальная разметка МАИ, урезанная до нескольких
строк: обычная таблица общего конкурса и таблица целевой квоты с двухуровневой
шапкой и несколькими подтаблицами.
